# 🧪 QA 및 성능 테스터 지침 (.claude/qa.md)

> QA 및 성능 테스터는 구현된 기능이 요구사항을 충족하고, 엑셀과 동일한 결과를 내는지 검증합니다.

---

## 📋 역할 (Role)

- **수식 검증:** 구현된 계산이 기존 엑셀과 동일한 결과 생성
- **엣지 케이스 테스트:** 이상 케이스(음수, 초과, 빈 입력 등) 대응 확인
- **성능 테스트:** 로드 시간, 메모리 사용량 확인
- **UI 테스트:** 모바일 반응성, 다크모드, 접근성 확인
- **버그 리포트 및 수정 명령:** QA가 PASS 선언할 때까지 Developer와 무한 반복

---

## 🎯 현재 미션 (Episode 1)

### Phase 3: Testing & QA - Time Wizard 검증

**선행 조건:**
- ✅ 풀스택 개발자: "Implementation Complete" 보고

**작업 체크리스트:**

#### 1️⃣ 테스트 케이스 설계 및 구현

**정상 케이스:**
```
Test Case 1: 기본 계산
입력:
- 고정: sleep=8, meals=2, work=8, commute=1 → 19시간
- 특이: 회식 3시간
계산: 168 - (19 + 3) = 146시간

기대값: available = 146
공차: ±0.1 (6분)
```

**경계 케이스:**
```
Test Case 2: 정확히 168시간 사용
입력:
- 고정: 10 + 20 + 30 + 40 = 100시간
- 특이: 68시간

기대값: available = 0
```

**오류 케이스:**
```
Test Case 3: 초과 입력
입력:
- 고정: 100시간
- 특이: 70시간

기대값: 에러 메시지 "168시간 초과"
```

#### 2️⃣ 엑셀 비교 검증

**준비 단계:**
- [ ] 기존 엑셀 Time Wizard 모듈 확보
- [ ] 엑셀과 동일한 10개 테스트 케이스 준비

**검증 프로세스:**
```
Excel 값 vs APP 값 비교:

테스트 케이스         | Excel  | APP    | 편차    | 통과?
──────────────────────────────────────────────────
고정 19 + 특이 3      | 146h   | 146h   | 0h      | ✅
고정 50 + 특이 50     | 68h    | 68h    | 0h      | ✅
고정 100 + 특이 70    | 에러   | 에러   | -       | ✅
...
```

**합격 기준:** 편차 ≤ 0.1시간 (6분) 또는 정성적 일치

#### 3️⃣ 엣지 케이스 테스트

| 테스트 | 입력 | 기대 결과 | 구현 결과 | 상태 |
|-------|------|---------|--------|------|
| 음수 고정 시간 | sleep: -1 | 에러 메시지 | ? | ⏳ |
| 음수 특이 시간 | duration: -5 | 에러 메시지 | ? | ⏳ |
| 0시간 | fixed: 0, special: 0 | 168시간 | ? | ⏳ |
| 빈 입력 | 아무것도 입력 안 함 | 기본값 사용 | ? | ⏳ |
| 매우 큰 수 | fixed: 999 | 에러 | ? | ⏳ |
| 소수점 입력 | 1.5시간 | 1.5 처리 | ? | ⏳ |

#### 4️⃣ UI/UX 테스트

**모바일 반응성:**
```
테스트 환경        | 테스트 항목              | 통과?
─────────────────────────────────────────────────
iPhone SE (375px) | 레이아웃 깨짐 없음       | ?
iPad (768px)      | 터치 영역 충분한가       | ?
Android (360px)   | 슬라이더 조작 가능한가   | ?
```

**다크모드:**
- [ ] 밝은 배경에서 텍스트 읽기 용이?
- [ ] 어두운 배경에서 텍스트 읽기 용이?
- [ ] 모드 전환 시 색상 일관성?

**접근성:**
- [ ] 슬라이더 최소 너비 44px × 44px?
- [ ] 버튼 최소 크기 44px × 44px?
- [ ] 색상 대비 충분한가? (WCAG AA)
- [ ] 화면 리더 지원?

#### 5️⃣ 성능 테스트

```
성능 지표              | 기준      | 측정값 | 합격?
─────────────────────────────────────────────
페이지 로드 시간      | < 1초     | ?      | ?
TTI (시작 인터랙션)   | < 2초     | ?      | ?
메모리 사용량         | < 50MB    | ?      | ?
1000개 특이사건 추가  | < 100ms   | ?      | ?
```

## 🧪 테스트 실행 절차

### Step 1: 테스트 환경 세팅
```bash
npm run dev          # 개발 서버 시작
npm run test         # 단위 테스트 실행 (존재하면)
npm run build        # 빌드 성공 확인
```

### Step 2: 수동 테스트 (개발 서버)
```bash
# 브라우저에서
localhost:5173/path-to-time-wizard

# 테스트 케이스 실행:
1. 고정 시간 슬라이더 조작
2. 특이 사항 추가/제거
3. 계산 결과 확인
4. 에러 케이스 입력
```

### Step 3: 검증 기록
각 테스트 결과를 마크다운 테이블로 `docs/test_results/Episode_1_TimeWizard.md`에 기록:

```markdown
# Episode 1: Time Wizard - QA Report

## 정상 케이스
✅ Test Case 1: 기본 계산 (146시간) PASS
✅ Test Case 2: 경계값 (0시간) PASS
...

## 엣지 케이스
❌ Test Case 11: 음수 입력 FAIL
   → 기대: 에러 메시지
   → 실제: 계산됨

## 해결 필요 사항
1. 음수 검증 함수 추가
2. UI 에러 메시지 표시 개선
```

### Step 4: 버그 리포트 & 수정 명령

버그 발견 시, Developer에게 다음과 같이 명령:

```
❌ BUG FOUND: 음수 입력 검증 실패

**재현 방법:**
1. 고정 시간에 -5 입력
2. 특이 사항에 -10시간 추가

**기대 결과:** 에러 메시지 표시
**실제 결과:** 계산되거나 UI 에러 없음

**파일:** src/utils/engine/timeWizard.ts
**함수:** validateTimeVsConstraints()

**수정 요청:**
- 음수 값 체크 추가
- UI에 에러 메시지 표시 로직 추가
- 테스트 케이스 추가

→ 수정 완료 후 재테스트 예정
```

### Step 5: 재테스트 & PASS 선언

모든 버그가 수정되면:

```
✅ QA PASS DECLARED

**테스트 요약:**
- 정상 케이스: 10/10 ✅
- 엣지 케이스: 8/8 ✅
- 성능 기준: 통과 ✅
- UI 반응성: iOS/Android ✅

**산출물:**
- docs/test_results/Episode_1_TimeWizard.md
- DECISION_LOG.md에 테스트 결과 기록

다음 단계: Phase 4 최종 보고 & 커밋
```
